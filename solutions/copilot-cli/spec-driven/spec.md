# 神経衰弱ゲーム仕様

## 目的

ブラウザで遊べる、1人用の神経衰弱ゲームを作成します。追加のサーバーや外部APIを使用せず、スタータープロジェクトだけで実行できるようにします。

## 技術条件

- TypeScript、HTML、CSSを使用する
- UIフレームワークを追加しない
- Viteの開発サーバーで動作する
- ゲームの状態遷移とDOM操作を分離する
- ゲームの状態遷移をVitestでテストできる構造にする
- 不一致時の表示保持は標準の`setTimeout`と`clearTimeout`で実装し、Vitestのフェイクタイマーで時間経過を再現できる構造にする
- 純粋な状態遷移はNode環境のVitestで、タイマーを含む制御層はフェイクタイマーでテストする
- DOM表示とブラウザ上のアクセシビリティ属性は手動確認の対象とし、DOM単体テストは必須としない
- `npm run typecheck`、`npm test`、`npm run build`が成功する

## ゲーム盤

- 4行4列の16枚のカードを表示する
- 8種類の絵柄を2枚ずつ使用する
- 絵柄はUnicode絵文字など、外部リソースを使わず表示できる方法で表現する
- ゲーム開始時とリセット時にカードをシャッフルする
- テストではカードの並びを明示的に指定できる
- ゲームの初期化処理は、順序を固定した山札を受け取れる構造にする
- 山札を指定しない通常のゲーム開始時だけシャッフルする
- 指定する山札は16枚かつ8種類の絵柄が2枚ずつの順序付きデータとし、実装側で複製して使用する
- 不正な山札を指定した場合は明示的なエラーにする
- シャッフルされた順序自体のランダム性は自動テストの対象外とし、カード組成と固定順の注入を確認する

## カードの状態

カードは次のいずれかの状態を持ちます。

- 裏向き
- 単独表向き（1枚目を選択した後、2枚目を選択できる状態）
- 判定待ち表向き（不一致の2枚を表示中で、ほかのカードを選択できない状態）
- 一致済み

## カードを選択する

- 裏向きのカードを選択すると表向きになる
- 一致済みのカードを選択しても状態は変わらない
- すでに表向きのカードを再度選択しても状態は変わらない
- 判定待ち表向きのカードがある間は、ほかのカードを選択しても状態は変わらない
- 1枚目と2枚目に異なるカードを選択する
- 2枚目を選択した時点で手数を1増やす

## 一致した場合

- 2枚の絵柄が同じ場合は一致済みにする
- 一致済みのカードは表向きのままにする
- 一致判定後は遅延を挟まず、即座に一致済み状態にする
- 次のカードを選択できるようにする

## 一致しなかった場合

- 2枚の絵柄が異なる場合は、両方を800ミリ秒間表示する
- 800ミリ秒は2枚目を選択した時点から数える
- 表示中はほかのカードを選択できない
- 799ミリ秒経過時点では両方が表向きで、入力がロックされたままとする
- 800ミリ秒後に両方を裏向きへ戻す
- その後、次のカードを選択できるようにする

## ゲームクリア

- 8組すべてが一致したらゲームクリアとする
- ゲームクリアを画面上に表示する
- 最終的な手数を表示する
- 最後の2枚目を選択した同じ状態遷移で、手数の加算、一致済み化、ゲームクリアを確定する
- ゲームクリア後のカード選択は無効とし、ゲーム状態を変更しない

## リセット

- リセットボタンを表示する
- リセットすると、カード、手数、選択状態、入力のロック、ゲームクリア状態を初期化する
- 判定待ちのタイマーがある場合は無効化する
- 無効化した古いタイマーのコールバックが実行されても、新しいゲームの状態を変更しない
- リセットボタンを選択した場合は、シャッフルした新しいカード配置でゲームを開始する
- テストからは、順序を固定した山札を指定してリセットできる構造にする
- 山札を指定したリセットではその順序を使用し、指定しない通常のリセット時だけシャッフルする

## 画面

- ゲーム名を表示する
- 現在の手数を表示する
- 4行4列のカードを表示する
- リセットボタンを表示する
- ゲームクリア時にメッセージを表示する
- 幅320 CSSピクセル、標準ズームの画面で、ゲーム領域の`scrollWidth`が`clientWidth`を超えず、すべてのボタンを操作できる

## アクセシビリティ

- カードとリセットには`button`要素を使用する
- キーボードだけでもカードを選択できる
- カードの状態を支援技術が識別できるラベルを付ける
- 裏向きのカードのラベルには絵柄の情報を含めない
- 表向き、一致判定待ち、一致済みのラベルには絵柄と状態を含め、それぞれを区別する
- ゲームクリアのメッセージは支援技術へ状態変化として通知する
- 色だけでカードの状態を表現しない

## 自動テストの受入基準

- 初期状態で16枚、8組、全カード裏向き、手数0、未クリア、入力可能である
- 1枚目の選択、同じカードの再選択、一致済みカードの選択を仕様どおり処理する
- 一致時は2枚目の選択で手数を加算し、タイマーを待たず一致済みにする
- 不一致時は入力をロックし、799ミリ秒では維持し、800ミリ秒で両方を裏向きにしてロックを解除する
- 判定待ち中の別カード選択で状態を変更しない
- 判定待ち中のリセットで古いタイマーを無効にし、新しいゲームへ影響させない
- 最後の1組が一致するとゲームクリアになり、最終手数を保持し、その後のカード選択で状態を変更しない
- リセットでカード、手数、選択状態、入力ロック、ゲームクリア状態を初期化し、指定した固定順の山札を使用できる

## 対象外

- 対戦機能
- オンラインランキング
- ユーザー登録
- データの永続化
- バックエンド
- 効果音
- 外部画像や外部API

- 型検査とビルドが成功する
- ブラウザで基本操作とレスポンシブ表示を確認できる
