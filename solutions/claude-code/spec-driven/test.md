# 自動テスト

`npm test`（Vitest）で実行される自動テストの一覧です。ゲームの状態遷移はDOM操作から分離されており、`GameController`（`src/game/gameController.ts`）に対する単体テストとしてすべて記述しています。

## `src/game/deck.test.ts`

- `createOrderedSymbolIds`: 8種類の絵柄をそれぞれ2枚ずつ、16枚分生成する
- `shuffle`: シャッフル後も要素の多重集合を保つ／元の配列を変更しない
- `buildDeck`: 順序を指定した場合はその並びをそのまま使う／順序を指定しない場合は8種類の絵柄が2枚ずつ含まれる山札を生成する

## `src/game/gameController.test.ts`

- 固定した山札順序でカードを初期化する
- 裏向きのカードを選択すると表向きになる
- すでに表向きのカードを再度選択しても状態は変わらない
- 一致した場合は即座に一致済みになり、手数が1増える
- 一致済みのカードを選択しても状態は変わらない
- 一致した直後に次のカードを選択できる
- 一致しなかった場合は判定待ちになり、手数が1増え、ほかのカードを選択できない
- 800ミリ秒未満では判定待ちのまま、800ミリ秒経過すると裏向きに戻る（Vitestのフェイクタイマーで検証）
- 判定待ち解除後は次のカードを選択できる
- 8組すべて一致するとゲームクリアになり、最終的な手数を保持する
- リセットすると、カード、手数、選択状態、ロック、クリア状態が初期化される
- 判定待ちのタイマーがある間にリセットすると、タイマーは無効化される（リセット後にタイマーが発火しても状態が変化しないことを検証）
- リセットボタンは判定待ち中でも常に有効（reset呼び出しが常に受け付けられる）

# 手動確認（ブラウザ）

以下は自動テストの対象外とし、`npm run dev`で起動したブラウザ上で確認します。

- 基本操作（カードを選び、一致・不一致・ゲームクリアまで一通り遊べる）
- 320ピクセル幅の画面で横スクロールが発生しない
- キーボードだけでカードとリセットボタンを操作できる
- 支援技術（スクリーンリーダー等）がカードの状態を識別できるラベルになっている
- 色以外の手段（枠線・アイコン・disabled状態など）でカードの状態が判別できる
