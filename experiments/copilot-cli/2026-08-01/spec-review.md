# 仕様のPlanレビュー

## 実行条件

GitHub Copilot CLI 1.0.77をShift+TabでPlanモードへ切り替え、`spec.md`だけを確認し、コードとファイルを変更せずに曖昧さ、矛盾、テストしにくい条件を報告するよう指示しました。

Planの確定前に、Copilot CLIから4つの選択質問がありました。Plan Readyの画面で内容を確認して終了し、この段階ではリポジトリのファイルが変更されていないことを確認しました。

## 指摘された項目

Planレビューでは、次の10項目が示されました。

- 完了条件が、提供していない`test.md`を参照している
- カードの状態モデルが曖昧
- 固定山札の形式と検証条件が未定義
- 通常のシャッフルと固定山札リセットの優先順位が不明
- 800ミリ秒の起点と799ミリ秒時点の状態が不明
- 判定待ち中のリセットと古いタイマーの扱いが不明
- 入力無効化とクリア後のカード選択の扱いが不明
- 最後の一致とクリア遷移の順序が不明
- 状態別の支援技術向けラベルが不足
- 320ピクセル幅と単体テストの境界が不明

## 採用した判断

- `test.md`参照を削除し、自動テストの受入基準を`spec.md`へ追加する
- 単体テストは状態遷移とタイマーを対象にし、DOM表示はブラウザで確認する
- クリア後はカード入力を無効化する
- 乱数品質はテストせず、山札の構成と固定山札を検証する
- 800ミリ秒は2枚目の選択から数え、799ミリ秒と800ミリ秒の境界を明示する
- 判定待ち中のリセット後は古いタイマーが新しいゲームへ影響しない
- 支援技術向けラベルで4状態を区別する
- 320 CSSピクセル幅で横スクロールを発生させない

採用内容を人が`spec.md`へ反映してから、同じセッションを通常モードへ戻して実装を指示しました。
